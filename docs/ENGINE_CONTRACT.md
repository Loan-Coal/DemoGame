## 1. Connection & auth

| Item | Value |
|------|-------|
| Base URL (dev) | `http://localhost:8000` |
| API version prefix | `/v1` (admin routes: `/v1/admin`) |
| Auth scheme | `Authorization: Bearer <API_KEY>` on **every** route except `GET /health` |
| API key (dev) | `API_KEY_SECRET` env var on the engine. Dev default literally `local_dev_secret_change_this_2026` — the game must be given the *same* value out-of-band. |
| Auth failure | HTTP 401, no detail body. |
| Player message cap | `player_message` ≤ `MAX_PLAYER_MESSAGE_CHARS` (1000). **Enforce client-side too** (non-empty, ≤1000). |

The key is a **shared secret**, not per-user. There are also scoped keys
(`API_KEY_GRAPH_WRITE`, `API_KEY_GRAPH_ADMIN`) but the base `API_KEY_SECRET` is sufficient
for everything DemoGame does in slice-1 (dialogue, action, reads, seeding).

**Secret handling:** read base URL + key from an uncommitted source (env var
`NPC_ENGINE_URL` / `NPC_ENGINE_API_KEY`, or a gitignored `Config/NpcEngine.ini`). Fail fast
with a clear message if missing. Never commit the key.

## 2. Response envelope — TWO shapes (critical)

The engine is **not** uniform. Your JSON layer must branch on endpoint:

### Shape A — raw model (dialogue + action only)
`POST /v1/dialogue` returns a bare `DialogueResponse`. `POST /v1/action` returns a bare
`{ "status": ... }`. No wrapper.

### Shape B — `OkEnvelope` (everything else: graph, npc state, seeding, reads)
```jsonc
{
  "data":  <payload>,      // the actual object/array — read this
  "meta":  <object|null>,  // pagination, warnings
  "error": <object|null>   // null on success
}
```
Read `.data` for the payload. Treat a non-null `.error` (or any non-2xx) as failure.

## 3. Endpoints DemoGame uses

### 3.1 Health — `GET /health`  *(no auth, no prefix)*
Liveness only (no DB/LLM probe). Envelope B.
```json
{ "data": { "status": "ok", "version": "<build-sha>" }, "meta": null, "error": null }
```
Use this for the smoke-test step 1 and as the "engine reachable?" probe.
For dependency readiness (LLM up) use `GET /readiness` → `{ "data": { "status": "ready|degraded", "llm": "ok|unreachable" } }`.

### 3.2 Dialogue (REST, slice-1 path) — `POST /v1/dialogue`  *(auth, raw shape A)*

**Request body** (`DialogueRequest`):
```jsonc
{
  "player_id":      "player_demo",        // REQUIRED — must be an existing Character node
  "npc_id":         "mira_innkeeper",     // REQUIRED — stable seed id
  "player_message": "Good evening, Mira.", // REQUIRED — 1..1000 chars
  "location_id":    "loc_tavern",         // optional
  "session_id":     null,                  // optional — pass back the one the engine returns to continue a convo
  "explicit_node_ids": []                  // optional — force specific graph nodes into context
}
```

**Response body** (`DialogueResponse`, RAW — no envelope). Model **all** of this now; display
only `npc_response` in slice-1:
```jsonc
{
  "npc_response": "Evening, traveler. Quiet night... so far.",  // the line to display
  "relation_deltas": { "trust": 0, "fear": 0, "affection": 1 }, // each -15..15
  "mood_update": "wary",
  "emotion": "wary",                       // may mirror mood_update
  "action": { "type": "speak", "target_id": null, "parameters": {} },
  "facial_expression": { "type": "neutral", "intensity": 0 },   // intensity 0..100
  "learned_facts": [],
  "memories_recalled": [],                 // memory node ids surfaced in context
  "session_id": "…",                       // pass this back on the next turn
  "cached": false,
  "degradation_level": "full",             // "full" = healthy; other = engine self-degraded (e.g. LLM slow)
  "audio_bytes": null                      // TTS — see §6. Over REST this is null/unreliable; audio comes via WS.
}
```
- 422 `{ "detail": { "code": "CHARACTER_NOT_FOUND", "message": "Character not found." } }`
  if `npc_id`/`player_id` resolve to no node. The internal id is **not** echoed.
- `npc_response` is the display field — **not** `text`/`reply`/`message`.

`ActionModel.type` is a closed set (engine coerces unknown → `"speak"`). `facial_expression.type`
is a closed expression set. Model these as Unreal enums with a safe default; do **not** hard-fail
on an unrecognized value (forward-compat — log + fall back to `speak`/`neutral`).

### 3.3 Dialogue (streaming, BUILD but DON'T wire in slice-1) — `WS /v1/ws/dialogue`  *(auth via header)*

Auth: send `Authorization: Bearer <key>` on the WS **handshake**. Bad/missing → server closes
with code `1008`. Max **5** concurrent connections per key.

Wire protocol (server → client JSON messages):
```jsonc
{ "type": "token", "data": "<chunk>" }    // 0..N of these, stream as they arrive
{ "type": "done",  "data": {              // exactly one, terminates the turn
    "degradation_level": "full",
    "emotion": "wary",
    "relation_deltas": { "trust": 0, "fear": 0, "affection": 1 },
    "action": { "type": "speak", "target_id": null, "parameters": {} },
    "facial_expression": { "type": "neutral", "intensity": 0 },
    "audio_bytes_b64": null               // base64 WAV when TTS produced audio, else null
} }
{ "type": "error", "data": "internal_error" }     // then close 1011
{ "type": "proactive_line", ... }         // NPC-initiated push during idle (slice-1: ignore)
```
Client → server: send **one** JSON `DialogueRequest` (same body as §3.2) after the socket opens.
Concatenate `token.data` chunks = the full `npc_response`; `done` carries the metadata.

> Scaffold a `FNpcEngineWebSocketClient` (FWebSocketsModule) that parses this protocol and
> exposes `OnDialogueChunk(FString)` / `OnDialogueComplete(FDialogueResponse)` delegates —
> but route slice-1 gameplay through the REST client. Streaming is **built, not wired**.

### 3.4 Player action report — `POST /v1/action`  *(auth, raw shape A)*
Applies a conservative relation delta or a currency transfer for a gameplay action.
```jsonc
{
  "action_type": "gift_item",      // closed set; currency actions: "buy_item"/"sell_item"
  "player_id":   "player_demo",
  "npc_id":      "mira_innkeeper",
  "intensity":   1,                 // optional, drives delta magnitude
  "counterparty_id": null,          // currency actions only
  "currency_amount": null,          // currency actions only
  "session_scope":   null,
  "currency_reason": null
}
```
Returns raw `{ "status": "ok"|"ignored", ... }`. Optional `X-Request-ID` / idempotency header
for currency. Slice-1: scaffold the call, optional to wire.

### 3.5 NPC state reads — *(auth, envelope B)*
- `GET /v1/npc/{npc_id}/state?include_relations=true&include_events=true`
  → `data: { character, relations[], events[] }`
- `GET /v1/npc/{npc_id}/emotion`
  → `data: { npc_id, label, valence, arousal, updated_at }`

Useful for debug overlays; not required for the smoke test.

## 4. Seeding — the game owns it (REST, no Python)

The engine has **no bulk "seed world" endpoint**. The world is built by upserting nodes and
edges through generic graph routes. DemoGame ships its own seed data (`Seed/slice1_tavern.json`)
and replays it on first connect via these two calls. Both are idempotent (MERGE semantics).

- **Upsert node:** `POST /v1/graph/nodes/{node_type}` body `{ "properties": { ... } }`
  (node_type e.g. `Character`, `Location`, `Faction`, `Item`). Returns envelope B.
- **Upsert edge:** `POST /v1/graph/edges/{edge_type}` body `{ "src_id": "...", "dst_id": "...", "properties": { ... } }`
  (edge_type e.g. `LOCATED_AT`, `RELATES_TO`, `MEMBER_OF`). Both endpoint nodes must already exist.
- **Check existence (for idempotency):** `GET /v1/graph/nodes/{node_type}/{node_id}` →
  envelope B with `data: null` (or 404) when absent.
- Richer inner-life (memories/beliefs/goals/secrets) lives under `/v1/admin/...`
  (`POST /v1/admin/memories/{character_id}`, etc.) — **out of scope for slice-1 seeding.**

Seed order (dependency-respecting): Locations → Factions → Characters → edges
(`LOCATED_AT`, `MEMBER_OF`, `RELATES_TO`). See `Seed/slice1_tavern.json`.

## 5. Player identity — DECISION

- **The game generates and owns `player_id`.** Format: `player_<8 lowercase hex>`, generated
  once per save profile and persisted to a gitignored save (`Saved/NpcEngine/player_id.txt`
  or a `USaveGame`). It is sent on every dialogue/action call.
- **Slice-1 default = `player_demo`.** The engine's existing seed already creates `player_demo`
  (`is_player: true`), so the default profile reuses it and the smoke test passes against an
  engine seeded by `make demo-seed` with **zero** extra steps.
- **When the game generates a NEW id**, it must first seed that Character node
  (`POST /v1/graph/nodes/Character` with `is_player: true`, see seed file for the property shape)
  **before** the first dialogue call, or dialogue returns 422 `CHARACTER_NOT_FOUND`.

Character property shape for the player node (from engine seed):
```jsonc
{ "id": "player_demo", "name": "Traveler", "archetype": "adventurer", "faction": "neutral",
  "biography": "A wandering adventurer.", "is_player": true, "is_active": true,
  "gossipy": 50, "credulity": 50, "honesty": 60, "currency_balance": 60 }
```

## 6. TTS extension point

`audio_bytes` (REST) / `audio_bytes_b64` (WS `done`) **already exist in the live contract** —
this is not a future field to invent. Slice-1 is text-only, so:
- Include an optional `audio` field in the Unreal response USTRUCT now.
- Over **REST** it is effectively `null` (Pydantic serializes raw `bytes` to a string; WAV is
  not valid UTF-8, so real audio is not transported by `/v1/dialogue`).
- Over **WS** it arrives as base64 in the `done` message (`audio_bytes_b64`).
- Add an `OnAudioReady(TArray<uint8>)` hook + a `ParseTTS` stub, marked `// TODO(TTS)`. Decode
  base64 → WAV → `USoundWaveProcedural` later. No audio work in slice-1.

## 7. Fallback contract (client-side, on top of engine self-degradation)

The engine already self-degrades (`degradation_level != "full"`, served fallback lines on LLM
timeout). The **client** adds a second layer:
- **Timeout / unreachable / non-2xx** → surface a canned fallback line
  (e.g. *"…(Mira seems distracted and doesn't respond.)"*), never crash, never block the game thread.
- All calls async (FHttpModule callbacks fire on the game thread — safe to touch UObjects).
- Recommended dialogue timeout: **30 s** (Ollama on CPU is slow; see README perf note). Health
  timeout: 3 s.

## 9. Smoke test (do BEFORE any Unreal code)

1. **curl/PowerShell, no Unreal:** `GET /health` → 200. Then one authenticated
   `POST /v1/dialogue` with `{player_id:"player_demo", npc_id:"mira_innkeeper", player_message:"Good evening."}`
   → 200 with a non-empty `npc_response`. This proves the engine + key + seed before any C++.
2. **In-editor (C++):** an Automation Spec **or** a `UFUNCTION(Exec)` console command that runs
   the same two calls through `NpcEngineClient` and logs `npc_response`. (Pick one and state it —
   "in-editor test" is otherwise ambiguous.)

PowerShell one-liner for step 1:
```powershell
$h=@{Authorization="Bearer $env:NPC_ENGINE_API_KEY"}
Invoke-RestMethod http://localhost:8000/health
Invoke-RestMethod -Method Post http://localhost:8000/v1/dialogue -Headers $h -ContentType application/json -Body (@{player_id="player_demo";npc_id="mira_innkeeper";player_message="Good evening, Mira."}|ConvertTo-Json)
```
